## Code audit findings

### PASS — SSH Registry and persistent OpenSSH configuration

- Private key contents are not stored in SQLite.
- Registry stores only identity-file paths.
- Key path is constrained to `/data/ssh/keys` by basename resolution.
- Key permissions are normalized to `0600`; SSH directories use `0700`.
- Generated config uses persistent `known_hosts` and `StrictHostKeyChecking accept-new`, not global `no`.
- Registry removal preserves the physical key file.
- Add/edit validation rejects whitespace/newline injection in host/user and validates port range.

### PASS — Docker integration

- Docker CLI is installed in the image.
- Host socket is an explicit deployment mount.
- Docker daemon failure degrades with a warning and does not stop Core startup.
- `DockerClient.getSummary()` is reusable by later `/status` health/operations work.

### PASS — Git/GitHub integration

- `GH_TOKEN` is preferred with `GITHUB_TOKEN` fallback.
- Fine-grained PAT validation uses an authenticated API request rather than classic PAT scope assumptions.
- GitHub credential helper setup avoids embedding the token in repository remote URLs.
- Git diagnostics redact the exact configured token and common GitHub token forms.
- Repository paths are constrained to `/workspace/repos`.
- Runtime E2E proves clone/pull/commit/push and redeploy persistence.

### BLOCKER — Codex `READ_ONLY` / `WORKSPACE` native sandbox in the deployed Coolify container

Codex maps:

- `READ_ONLY` -> `--sandbox read-only`
- `WORKSPACE` -> `--sandbox workspace-write`
- `FULL_ACCESS` -> `--dangerously-bypass-approvals-and-sandbox`

The deployed container produced `bwrap: No permissions to create a new namespace` while operating under the sandboxed profile. `FULL_ACCESS` works and has passed SSH/Docker/Git E2E, but Phase 9 cannot be marked fully `DONE` until `READ_ONLY` and `WORKSPACE` are runtime-verified or the container-compatible profile strategy is deliberately revised.

No silent automatic fallback to `FULL_ACCESS` should be added: a failed safety boundary must fail visibly rather than unexpectedly widening privileges.

### NOTE — Antigravity profile enforcement is intentionally PARTIAL

Antigravity does not expose an equivalent native sandbox boundary in the current adapter. The adapter clearly reports `executionProfiles: PARTIAL`; `READ_ONLY` removes permission bypass while `WORKSPACE`/`FULL_ACCESS` use prompt guards plus current non-interactive compatibility. This is not treated as a hidden security guarantee.

### NOTE — Telegram polling `409 Conflict`

Repeated `409 Conflict` remains an independent operations issue caused by more than one polling process using the same Bot Token. It does not invalidate Phase 9 infrastructure E2E, but production deployment should retain only one polling instance.

## Final audit verdict
