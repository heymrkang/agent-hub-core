## Code audit findings

### PASS — SSH Registry and persistent OpenSSH configuration

- Private key contents are not stored in SQLite.
- Registry stores only identity-file paths.
- Key path is constrained to `/data/ssh/keys` by basename resolution.
- Key permissions are normalized to `0600`; SSH directories use `0700`.
- Generated config uses persistent `known_hosts` and `StrictHostKeyChecking accept-new`, not global `no`.
- Registry removal preserves the physical key file.
- Add/edit validation rejects whitespace/newline injection in host/user and validates port range.

### PASS — Docker integration

- Docker CLI is installed in the image.
- Host socket is an explicit deployment mount.
- Docker daemon failure degrades with a warning and does not stop Core startup.
- `DockerClient.getSummary()` is reusable by later `/status` health/operations work.

### PASS — Git/GitHub integration

- `GH_TOKEN` is preferred with `GITHUB_TOKEN` fallback.
- Fine-grained PAT validation uses an authenticated API request rather than classic PAT scope assumptions.
- GitHub credential helper setup avoids embedding the token in repository remote URLs.
- Git diagnostics redact the configured token and common GitHub token forms.
- Repository paths are constrained to `/workspace/repos`.
- Runtime E2E proves clone/pull/commit/push and redeploy persistence.

### PASS — Codex Execution Profile isolation

The first implementation using Codex native Linux sandbox inside the Coolify container hit nested `bwrap` namespace restrictions. A legacy Landlock attempt also proved incompatible with the deployed Codex runtime. The final implementation deliberately moved restricted execution into short-lived sibling Docker helper containers and uses Docker mounts as the outer isolation boundary.

Verified behavior:

- `READ_ONLY`: `/workspace` mounted `ro`; runtime write attempt returns `Read-only file system`.
- `WORKSPACE`: `/workspace` mounted `rw`; runtime file creation and content verification succeed.
- Restricted helpers do not receive the Docker socket, SSH keys, GH/GitHub token, or the full `/data` tree.
- Restricted helpers use dropped capabilities and `no-new-privileges`.
- `FULL_ACCESS`: explicit privileged application profile used for trusted SSH/Docker/Git infrastructure work.
- There is no silent fallback from a restricted profile to FULL_ACCESS.

This resolves the Phase 9 runtime blocker.

### NOTE — Antigravity profile enforcement is intentionally PARTIAL

Antigravity does not expose an equivalent native sandbox boundary in the current adapter. The adapter reports `executionProfiles: PARTIAL`; this is not treated as a hidden security guarantee.

### NOTE — Telegram polling `409 Conflict`

Repeated `409 Conflict` is an independent operations issue caused by more than one polling process using the same Bot Token. It does not invalidate Phase 9 infrastructure E2E. Production should retain only one polling instance.
